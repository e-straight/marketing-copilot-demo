Readiness check

  • The workshop project appears under Projects.
  • WorkIQ returns your calendar results.

Elijah's presenter runbook

Build the BRK 999 message and workflow tracker, step by step.

Follow this sequence live. Elijah uses the BRK 999 group chat as the facilitator example; participants use their own chat.

  1. 1

    Timing: 3 minutes

    Introduce the scenario

    Demo actions

    Explain that BRK 999 work is scattered across Teams messages and files. Use two examples: Elijah needs to update the slide deck, and Ashley has added comments to the script document. The goal is a workflow tracker that shows the item, owner, status, location, and next action.

    Suggested prompt

    No prompt yet. Show the problem before showing the tools.

    Expected result

    The audience understands the tracker is the outcome, not a feature tour.

    Handoff

    “First, we need the app connected to the right project and work context.”

    Fallback

    If the live files are unavailable, use the slide deck and commented script examples shown here.

  2. 2

    Timing: 7 minutes

    Install and sign in

    Demo actions

    Use the Setup tab. Download the app, open it, click Sign in to GitHub, finish browser authorization, and return to the app.

    Suggested prompt

    No prompt. Pause while participants complete sign-in.

    Expected result

    Elijah and participants see their GitHub account in the app.

    Handoff

    “Now let’s locate the few app surfaces we will use today.”

    Fallback

    If someone cannot install, pair them with a neighbor so they can still complete the workflow.

  3. 3

    Timing: 5 minutes

    Orient to the GitHub Copilot app

    Demo actions

    • Projects: Use a Project for ongoing work that needs context to stay together across sessions. A chat is better for a quick, standalone question or draft using only that conversation's context. BRK 999 belongs in a Project because setup, source context, tracker artifact, automation, and later updates need to stay together.
    • Sessions: Give one focused task to each session, such as gathering Teams context or checking the tracker.
    • Customize: Find the skills and connectors used by the demo, including WorkIQ for permitted Microsoft 365 context.
    • Automations: Save the Teams-to-tracker check so it can run on a schedule or on demand.
    • Artifacts and canvases: View or edit one specific output, such as the BRK 999 tracker.
    • Dashboards: Scan several workstreams, sessions, or statuses in one overview instead of opening each output.

    Suggested prompt

    No prompt. Keep this orientation under five minutes.

    Expected result

    Participants know where the project, working session, Microsoft 365 connection, tracker artifact, and automation will live.

    Handoff

    “Let’s open one durable Project for the tracker.”

    Fallback

    If a surface is not available in a participant build, describe its role and continue from a regular session.

    Terminology reference: GitHub Copilot app quickstart.

    Demo actions

  6. 6

    Timing: 8 minutes

    Create the workflow tracker

    Demo actions

    In the active Project session, send the prompt below. When the BRK 999 tracker artifact card appears above the composer, click it to open the artifact surface. Check the slide deck and Ashley's commented script rows before continuing.

    Suggested prompt

    Create a Markdown artifact named BRK 999 tracker from these results. Use columns for work item, owner, status, location or source, next action, and last updated. Keep source links. Use Needs confirmation when the evidence is incomplete.

    Expected result

    A readable tracker that shows where each item lives and what should happen next.

    Handoff

    “This is a useful snapshot. Now let’s make the update process repeatable.”

    Fallback

    If a native or custom canvas is unavailable, create the same tracker as a Markdown table or spreadsheet artifact.

  7. 7

    Timing: 8 minutes

    Build the Teams-to-tracker automation live

    Demo actions

    1. Open Automations, click Create automation, then click Create manually.
    2. Name it BRK 999 tracker check and leave Run in the cloud off so it uses the local signed-in WorkIQ connection.
    3. Choose the scheduled trigger and set this scheduled check to run every 15 minutes.
    4. Paste the prompt below and select the workshop repository or local folder.
    5. Open the dropdown next to Create and click Create and run.

    Suggested prompt

    Check my permitted BRK 999 Teams context for new messages about items already in the BRK 999 tracker artifact. Update owner, status, next action, source, and last updated only when the message is explicit. Put conflicts or missing details in Needs confirmation. Preserve the source link for every change.

    Expected result

    A saved local automation named BRK 999 tracker check, scheduled every 15 minutes, with its first run started.

    Handoff

    “Let’s test this with one message we already understand.”

    Fallback

    If automation creation is unavailable, save and run the same instruction on demand. The workflow still works; only the trigger changes.

  8. 8

    Timing: 4 minutes

    Verify the tracker update

    Demo actions

    1. On the Automations page, wait for the BRK 999 tracker check run to finish and open its run result.
    2. Return to the BRK 999 Project and open the BRK 999 tracker artifact card.
    3. Compare the changed row with the linked Teams source. Confirm the owner, status, next action, and timestamp are accurate.
    4. To test again without waiting 15 minutes, return to Automations and click the play button on the automation card.

    Suggested prompt

    Show me the source evidence for each proposed tracker change before applying it.

    Expected result

    One verified tracker update with its source and timestamp preserved.

    Handoff

    “We connected messages, an artifact, review, and a repeatable workflow.”

    Fallback

    If no new message is available, use an existing known message and demonstrate the comparison without writing a duplicate update.

  9. 9

    Timing: 3 minutes

    Explain which Copilot app fits

    Demo actions

    Open the Compare apps tab. Position the choice as best fit, not a hard product boundary.

    Suggested prompt

    No prompt. Use the concise comparison on the next tab.

    Expected result

    Participants understand why this durable, multi-step tracker workflow fits the GitHub Copilot app and where Microsoft Copilot may be interchangeable.

    Handoff

    “Choose the surface that matches where the work lives and how much orchestration it needs.”

    Fallback

    For licensing or availability questions, point to current official product pages rather than improvising.

  10. 10

    Timing: 2 minutes

    Close with participant next steps

    Demo actions

    Ask participants to finish their tracker, test one update, and identify one recurring work signal they could automate safely.

    Suggested prompt

    Review my tracker for missing sources, unclear status, or next actions that need confirmation. Suggest one narrow, review-first automation I could test next.

    Expected result

    Each participant leaves with a tracker, a tested update method, and one practical next automation.

    Handoff

    Move to Q&A.

    Fallback

    If time is short, skip the prompt and restate the three outcomes: visible work, traceable sources, and reviewed automation.

Quick guide

Which app should I use?

Start with where the work is and what you need to do next.

Use GitHub Copilot when...

  • You want to keep a project, source files, sessions, and automation together.
  • You want separate sessions or agents to handle different parts of the work.
  • You need a custom tracker view or a task that runs again on a schedule.
  • The work may later involve a repository, issue, pull request, or code change.
GitHub Copilot app quickstart

Use Microsoft Copilot when...

  • Your work mostly happens in Microsoft 365, such as Teams, Outlook, Word, or PowerPoint.
  • You want quick help with everyday personal work.
  • You need to summarize a Teams thread, draft a reply, or turn meeting notes into actions.
  • You do not need a repository, several work sessions, or a software workflow.
Microsoft Copilot app

Either app can work when...

  • You want to brainstorm, summarize, research, or draft.
  • You need a quick outline, table, or first draft.
  • You do not need a long-running repository workflow or a deeply Microsoft-first experience.
  • You need Microsoft 365 context but also want the work to continue in a Project; WorkIQ can bring permitted context into GitHub Copilot.

Product details can change. Check the current GitHub Copilot app quickstart and Microsoft Copilot app page.

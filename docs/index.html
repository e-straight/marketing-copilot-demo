    How to explain GitHub

    Use this analogy: “GitHub is like OneDrive for a project, plus permanent version history, review, and a shared task trail. It was built around code, but the useful idea is broader: the team can see what changed, why it changed, and what should happen next.”

    • Repository: the project's shared folder and its history.
    • Commit: a saved checkpoint that records a set of changes.
    • Pull request: a proposed change people can review before it becomes official.

    Orient to the GitHub Copilot app

    Demo actions

    • Projects: Use a Project for ongoing work that needs context to stay together across sessions. A chat is better for a quick, standalone question or draft using only that conversation's context. BRK 999 belongs in a Project because setup, source context, tracker artifact, automation, and later updates need to stay together.
    • Sessions: Give one focused task to each session, such as gathering Teams context or checking the tracker.

    • Automations: Save the Teams-to-tracker check so it can run on a schedule or on demand.
    • Artifacts and canvases: View or edit one specific output, such as the BRK 999 tracker.
    • Dashboards: Scan several workstreams, sessions, or statuses in one overview instead of opening each output.

    Repo sessions and Projects

    A repo is where Copilot performs coding work; a Project is the persistent coordinator for a larger outcome.

    Repo session example: To prepare for Microsoft Ignite, use a repo session to update one demo app, fix a bug, test it, or create a pull request. The session works in an isolated checkout of that specific repository.

    Project example: Use a Microsoft Ignite readiness Project to maintain the overall plan and coordinate multiple sessions, such as updating the demo app in one repo, presentation materials in another, tracking decisions, and running recurring readiness checks.

    A Project does not contain or replace the repos. It retains the broader context and delegates work to repo-backed sessions, including sessions across multiple repositories.

    Plugin, skill, or MCP server?

    Plugin: An installable bundle that can package custom agents, skills, hooks, MCP configuration, and app extensions. Use one when you want a ready-made toolkit, such as a testing plugin that includes review guidance and a connection to test results.

    Skill: A reusable recipe of instructions, scripts, and resources for how Copilot should perform a task. Use one when you want consistent steps, such as your team's release-note process.

    MCP server: A live connection to an external tool or data source. Use one when Copilot needs current information or needs to take an allowed action, such as accessing permitted Microsoft 365 context through WorkIQ.

    AI credits

    Analogy: Credits work like a phone data plan. Each request uses some credits, and more powerful models generally use more.

    Cost drivers: Credit usage varies by model and task complexity. Simple requests typically use fewer credits than complex tasks using more powerful models.

    Check usage: Open Personal Usage V2 in Power BI under Apps > AI Usage and Impact.

    Model selection and switching

    How: Click the model name below the prompt box. You can switch models at any point during a session.

    Start with Copilot Fusion when it is available. Fusion routes work and, when useful, orchestrates multiple enabled models so you do not need to choose one for every step.

    Choose the effort level for the task: Standard for everyday work, High for challenging work and deeper reasoning, and Max for the most demanding tasks.

    If the picker shows Auto instead, use Auto for general work. Its Efficiency, Balance, and Intelligence tiers prioritize cost, a middle ground, or quality.

    Choose a specific model when you need its particular behavior or your organization requires it.

    Cost considerations: Each model is billed at its normal rate. Paid plans currently receive a limited-time 30% discount on model costs with Fusion.

    Rule of thumb: Start with Fusion Standard. Move to High or Max when needed, then switch back to Standard.

    Availability depends on the Copilot surface, plan, rollout, and organization model policies.

Quick guide

Which Copilot experience should I use?

Choose based on where the work lives, how you prefer to work, and the outcome you need.

Use GitHub Copilot app when...

  • You want to keep a project, source files, sessions, and automation together.
  • You want separate sessions or agents to handle different parts of the work.
  • You need a custom tracker view or a task that runs again on a schedule.
  • You want to install or manage plugins, skills, and MCP connections directly from Customize.
  • The work may later involve a repository, issue, pull request, or code change.
GitHub Copilot app quickstart

Use GitHub Copilot CLI when...

  • You prefer terminal workflows.
  • You want Copilot to inspect or change files and run commands from the current working directory.
  • You need a scriptable or keyboard-first workflow.
  • You are comfortable reviewing commands, file changes, and permission requests before approving them.
  • You want to use supported skills, plugins, and MCP connections from the command line.
GitHub Copilot CLI quickstart

Use Microsoft Copilot Chat or Cowork when...

  • Your work mostly happens in Microsoft 365, such as Teams, Outlook, Word, or PowerPoint.
  • You want quick Chat help or delegated, multi-step knowledge work in Cowork.
  • You need to summarize a Teams thread, draft a reply, or turn meeting notes into actions.
  • You want to use or create Microsoft Copilot agents; availability varies by account, license, and organization settings.
  • Your organization uses Microsoft 365 Copilot or Copilot Studio to publish governed plugins, connectors, actions, skills, or MCP-backed tools.
  • You do not need a repository, several work sessions, or a software workflow.
Microsoft Copilot app

Use Microsoft Copilot Code when...

  • You want to describe an app, dashboard, automation, website, or script in plain language and watch it take shape in a live preview.
  • Your solution should use permitted Microsoft 365 work context such as documents, email, meetings, or calendar.
  • You want to build locally or in a secure cloud project, with optional GitHub repository and pull-request workflows.
  • You want to publish a small internal app or share an organization-scoped static app from a cloud project.
  • You have access to the Frontier preview; availability, licensing, and features may change.
Microsoft Copilot Code preview

More than one can work when...

  • You want to brainstorm, summarize, research, or draft.
  • You need a quick outline, table, or first draft.
  • You do not need a long-running repository workflow or a deeply Microsoft-first experience.
  • You need Microsoft 365 context but also want the work to continue in a Project; WorkIQ can bring permitted context into GitHub Copilot.

The standalone Microsoft Copilot app offers agents, but it does not use the same direct end-user Customize experience as the GitHub Copilot app. Deeper Microsoft extensibility is available through Microsoft 365 Copilot and Copilot Studio, and is commonly published or governed by approved makers or administrators. Copilot Code is a Frontier preview, so capabilities and availability can change.
